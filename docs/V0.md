# Persistent v0 task runner

The owner approved custom v0 development for compact contexts, reliable recovery
and deterministic verification. `autocoder-task` is the application entry point;
`autocoder` retains the original Stage 0 commands and frozen experiments.

## Project policy

Use an explicit JSON file outside tracked source for machine-specific policy:

```json
{
  "repository": "/absolute/path/to/project",
  "state_dir": "/home/phil/.local/share/autocoder/v0",
  "endpoint": "http://127.0.0.1:11434",
  "model": "qwen3.5:9b",
  "readable_paths": ["src/module.py"],
  "editable_paths": ["src/module.py"],
  "checks": [{
    "name": "regression",
    "kind": "tests",
    "language": "python",
    "command": ["/usr/bin/python3", "tests/regression.py"],
    "regression_pattern": "expected regression failure",
    "timeout": 30
  }]
}
```

Commands are trusted operator configuration, never model-generated shell. They run
inside an offline snapshot containing tracked files, with `/work` as the working
directory. Configure a literal expected failure signature to distinguish the target
regression from unrelated/environment failures. A passing baseline is inconclusive
for this initial bug-fix workflow and returns `NEEDS_USER`.

Only listed source paths are readable/editable through the gateway. Existing
files are supported; creating/deleting/renaming files is not yet supported. Tests,
configuration, credentials and embedded test regions are protected. Additional
project-specific verification files can be listed in `protected_paths`. An intentional
test/config edit requires identifying that exact file in `approved_test_paths`.
Submodules, checkout filters, symlinks and hard links are rejected.
The initial handoff schema expects Git SHA-1 repositories. Repositories
are capped at 10,000 tracked files/100 MB, with editable text files at 256 KB.
Binary assets can be copied for checks but cannot be edited.

## Commands

```sh
uv sync --locked
uv run autocoder-task --config /path/project.json start --request-file /path/task.txt
uv run autocoder-task --config /path/project.json status TASK_ID
uv run autocoder-task --config /path/project.json events TASK_ID --follow
uv run autocoder-task --config /path/project.json diff TASK_ID
uv run autocoder-task --config /path/project.json evidence TASK_ID
uv run autocoder-task --config /path/project.json evidence TASK_ID --ref EVIDENCE_SHA256
uv run autocoder-task --config /path/project.json cancel TASK_ID
uv run autocoder-task --config /path/project.json resume TASK_ID
```

Start/resume emit JSONL events followed by the final JSON report. State lives under
`state_dir/projects/PROJECT_ID/TASK_ID`, protected by a task lock. Evidence files
are addressed by SHA-256; the journal contains references and hashes, not source
bodies. The original checkout and dirty files are preserved. Successful changes
are committed on `autocoder/task-TASK_ID`; its worktree remains available.

`approve`/`refuse` record the user's decision about the concrete diff. Approval
prints a manual integration command; the application does not merge or push.
`mark-integrated` requires prior approval and verifies that the task commit is
actually an ancestor of the original checkout's HEAD. CI/hardware/human acceptance
remain separate report fields. Do not use `approve` merely to mark an agent's own
review as human acceptance.

## Terminal interface

```sh
uv run autocoder-tui --config /path/project.json
uv run autocoder-tui --config /path/project.json --task-id TASK_ID
```

The native Python `curses` client invokes the same headless CLI and consumes its
JSONL events. It requires an interactive terminal; it adds no service or dependency.

| Key | Action |
| --- | --- |
| `n` / `o` | Enter a new task / open an existing task ID |
| `v` | Show phase/tool events and evidence references |
| `s` / `d` | Show status / retained worktree diff |
| `e` | List recent evidence references, or enter a SHA-256 to inspect its content |
| `x` / `r` | Request stop / resume using the existing recovery checks |
| `a` / `j` | Approve / reject; type `approve` / `refuse` to confirm |
| Up/Down, Page Up/Page Down | Scroll the current view |
| `q` | Quit when idle, or detach an event reader |

Enter submits a prompt; Escape cancels it. New task requests are a single line,
limited to 8192 bytes; use the headless request-file command for multiline input.
The display retains the last 2000 lines, clips each at 4096 characters, and omits
individual output lines above 64 KiB. Complete evidence remains available through
the CLI and journal. Source/model terminal controls are filtered before display.
Diff inspection requires the task's worktree lock to be released.

While this UI owns a running start/resume command, quit and Ctrl-C do not abandon
the controller. Request stop and wait for its bounded checks to finish, then quit.
Attaching to an existing task only starts an event reader: quitting that reader
leaves the task running. An external terminal/process crash uses the same journal
recovery as a headless crash. Approval records a decision and prints integration
instructions; it never performs a merge.

For optional exact-commit GitHub Actions plans and inspection, see [CI.md](CI.md).

## Budgets, cancellation and recovery

V0 defaults: 600 seconds, 49,152 input tokens, 8,192 output tokens, 60 total tool
calls, 20 tool calls per phase and three repairs. These are application defaults,
not changes to the Stage 0 benchmark limits. Requests reserve conservative input
bytes plus template/output capacity and leave 20% context headroom. Per-endpoint
file locks under `~/.local/share/autocoder/inference-locks` serialize inference
across this user’s project processes, including projects with different state
roots. URL aliases for one physical server are not recognized as the same backend;
use a common endpoint origin.

Cancellation interrupts inference; synchronous checks stop at their configured
bounded deadline (at most 120 seconds). Resume validates the frozen policy/private
assets, journal chain, branch/repository identity, file hashes and pending writes.
One restart/replan is allowed. Elapsed wall time and reserved usage survive crashes;
downtime counts toward the task deadline. Torn journals or concurrent file changes
require manual inspection. Pending applied edits/commits are observed, not replayed.

Within a phase, assistant/tool messages are retained using the native Ollama
[tool-result protocol](https://docs.ollama.com/capabilities/tool-calling). At the
75% context threshold the coordinator resets to current source, the validated
plan and bounded operation summaries. Phase boundaries start fresh contexts;
private oracle results and previous phase transcripts are never inherited.

## Navigation and dependencies

`rg` and bounded reads work without Serena. Enable `serena` only with a separately
prepared `serena_runtime` and its `serena_runtime_sha256`. The process runs offline
in a cgroup with a mirror of approved source, a read-only runtime, two CPUs, 64
tasks, 2 GB resident memory and 8 GB virtual address space. Node/Pyright and Rust
analyzer are independently installed tools; no Serena imports enter this package.
Changed source invalidates the mirror and restarts its index. Unknown returned
paths are filtered; unvalidated line locations are flagged. No shared writable
language-server/compiler caches are used.

Checks use `/usr` Python's standard library by default. Rust checks mount the
resolved Rust toolchain read-only at `/toolchain`. A Python check may instead name
a reviewed directory in `runtime` with `runtime_sha256`; it appears read-only at
`/toolchain`. No untrusted install/build hook runs on the host. An optional `preparation` policy
lists at most eight artifact records (`name`, `url`, `sha256`, `max_bytes`) and a
trusted named command with `language`/`timeout`. The controller fetches inert bytes
from HTTPS (loopback HTTP is allowed for local tests), verifies digests/size caps,
and mounts only those artifacts read-only at `/artifacts`. The configured command
runs offline against a source snapshot and writes `.autocoder-deps`. Tracked input
changes, symlinks, hard links, special files or oversized output block publication.

Prepared outputs are copied into private task state, hashed and durably published;
checks mount them read-only at `/deps`. Reuse verifies their content digest. Rust
preparation also receives its read-only compiler at `/toolchain`. The model cannot
request downloads or change these commands. Missing preparation/dependencies block
verification; there is no unrestricted installer or host fallback.

Prepare a new navigation runtime from the independent lock and a reviewed local
Node executable (the helper refuses to overwrite an existing runtime):

```sh
uv run python scripts/prepare_serena_runtime.py \
  --runtime /absolute/path/outside/repository/serena-runtime \
  --node /absolute/path/to/node
```

It prints the two runtime policy fields to record. Different runtime locations can
produce different content digests; pin the actual prepared runtime. The existing
qualified host runtime uses 76 locked package versions and system Python 3.12.3.

Private Python/Rust acceptance cases may be configured through `oracles`, with
`language`, `entry`, and an external `cases_file` containing JSON argument/expected
records. Keep both the case data and any case generator outside the target
repository so source access cannot reveal expected answers. Rust also needs an external reviewed argument-only `driver`. Expected
values stay in the controller; only arguments reach candidate execution. Private
failures are terminal and never enter the public repair context. Without configured
oracles, `held_out` is explicitly `not_run`.

## Acceptance status

Local unit/isolation verification and live tasks are recorded in the
[v0 evidence report](evidence/V0_IMPLEMENTATION_2026-10-19.md). Two projects can be configured for the available endpoint.
The owner explicitly requested skipping the two-server test because only one
endpoint is available. SPEC 1.1 defers independent-server and server-outage
acceptance; neither was run. The current single-endpoint v0 acceptance scope is
locally verified. This does not establish remote CI or human acceptance of task patches.

The initial implementation has no automatic state migration across incompatible
policy/schema changes. A changed effective policy or private asset digest is
refused on resume; retain the recorded controller revision for old task recovery.
The full verification suite runs with `uv run pytest`; benchmark registrations
remain unchanged and independently checksum-bound.
